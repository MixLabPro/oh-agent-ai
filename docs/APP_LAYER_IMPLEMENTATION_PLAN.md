# Agent City 插件 APP 实施计划与验收台账

版本：v0.2 · 日期：2026-10-03
依据：AGENT_VITALS_APP_LAYER_ARCHITECTURE_SPEC.md v0.2。
首个项目范围：规格 M0–M2，交付可独立安装、授权、启动、取数、更新、回滚、

## §0 唯一完成标准

固定宿主构建 H，使用两个真实签名分发物 City C1/C2，从宿主应用管理入口完成：

~~~text
发现C1 → 安装预览/授权 → 启动独立City → 真实取数/交互/导出
→ 独立发布C2 → 更新预览/确认 → C2运行 → 显式回滚C1
→ 停用/撤销 → 卸载 → 重装/重新授权 → 偏好按策略恢复
~~~

记录 H、C1、C2 的版本与包哈希、平台、发布目录序号、实际运行revision、grant版本、
测试输入窗口与数据revision、CI结果及真机录屏。更新 City 时 H 的构建标识不得变化。
fixture、独立窗口、目录移动或一次安装成功只能证明局部，不得标记整项目完成。

本次文档重写完成不等于 M0–M2 已实现。以下任务均按代码与运行证据独立验收。

## §1 工作方式与当前基线

每批按分析 → build → 测试 → subAgent独立验收推进。分析先确认调用链、数据/包契约、
失败与恢复路径；实现保留现有未相关改动；验收使用实际入口和反例。
问题修复后复验，报告验收范围与未覆盖项。当前仓库有多项并行改动，禁止通过全量
格式化、重置、刷新所有golden或混合提交整理它们。

City 当前在 desktop React features/city 下，TS构建模型，模型含Map；
sessions/findings/timezone为取数入口，seed命令包含写操作。现状不是独立插件。
实施前生成 command inventory，以实际入口为准，不把“143命令减少”当验收结果。
纯移动与接线/功能分批提交，保留可追溯历史；尚未提交的文件不虚构历史证明。

macOS生产实跑必须从正式 .app bundle 启动，宿主菜单栏不运行裸二进制。
新City应用同样按系统应用路径启动；本地dev只能使用脱敏fixture，
不得用弱化签名/身份检查的dev配置完成生产验收。

## §4 推荐迭代批次与阶段退出

### B0：冻结边界与验证运行路线（C0–C3）

先交付最小 .app 的权限/IPC实测与schema，不先投入整城搬迁。
明确 app-local 会话摘要的授权字段、JSON格式、opaque钻取、SDK错误，
以及签名如何验证整包、平台身份如何证明真实连接者。
若OS沙箱与IPC路径不能同时成立，修订启动/隔离方案并复验；不能降级为
未验证外部进程直接访问authority。

M0退出：C0–C3证据齐全。它证明路线可行，不证明City插件已交付。

### B1：完成可安装运行的City（C4–C9）

通过已有query聚合生成投影，保留City TS模型与无头规划。
先提供SDK与原生桥，再接独立City包、安装器和宿主UI。默认素材随包走，
无需引入第二应用或皮肤货架。应用只获得已声明且批准的字段和控制。

M1退出：用户从宿主入口安装、授权和启动真实City；已有核心功能在本机真实数据上
运行，应用崩溃或宿主离线时工作台/摄入正常。不能在此宣布“整个闭环完成”。

### B2：完成独立发布与全生命周期（C10–C13）

保持宿主H不变，发布City release 1/2；确认更新、实际运行、回滚和卸载。
旧状态可恢复，新增权限需要重新授权，离线旧版可运行。
针对实际安装/更新路径注入失败，而不是只测低层ObjectStore返回值。

M2退出：全部G01–G12与§5矩阵有证据，独立验收通过；这才是首项目完成点。
无正式签名密钥/notarization或发布渠道时可继续本地构建/fixture，但真实发布门保持未完成。

## §7 关联规格与政策修订清单（C0/C1）

1. 扩展SPEC明确“数据扩展不可执行”与“官方独立plugin_app执行包”是不同通道；
   修订相关边界和引用，不能把旧安装器默认扩权。
2. app index独立版本化并由独立发布门校验；catalog-index-v1继续严格未知字段拒绝。
   新信任字段只进入app契约，后续data/content索引演进须发新版本或明确兼容方案。
3. AGENTS.md登记新增官方应用公共下载与受限本机app-local取数，保持用户数据不上传。
   独立进程不等于沙箱，政策描述必须与C2实测相符；第三方数据披露仍需独立决策。
4. app文件集合持久化、应用台账/权限、状态恢复与高水位独立建模；
   不以已有JSON ObjectStore验收替代可执行多文件包的验证。
5. content_pack细化留待C15：格式/URI/解码预算/许可/默认包不可卸载与历史保留；
   本次只要求City随包默认素材可用，不新增收费墙或市场基建。
