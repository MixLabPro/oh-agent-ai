# City 路网优先：当前代码优化方案

日期：2026-10-09。状态：建议实施，本文不代表代码已完成。
依据：worktree-city-network-first @ 90399ced，调研时工作区干净。
关联：CITY_NETWORK_FIRST_CODE_DESIGN.md、CITY_MODEL_PHYSICAL_INVARIANTS_SPEC.md。

## 1. 当前结论

保留 geography、NetworkPatch、现有连接候选与几何工具。先统一候选接受规则，再接入真实入口和后置选址，
最后整合求解与展示。不继续以增加圆环、搜索档位或放宽判据作为主要优化手段。
圆环、服务环和桥头圈可保留为候选形态，但都须经过相同终筛，不能因形态不同取得安全豁免。

已完成：端点高度盲区修正、连接器草稿事务、离线拆分拒绝与原宽度继承、设施旁孤立路的主网判断。
尚未完成：完整道路包络检查、入口真实路径、生产后置选址、字典序事务求解、最终展示图验收、整图预算。
本轮未重新跑120岛普查或截图，旧评审数字不能作为当前版本的验收结果。

## 2. 当前证据与优化落点

| 代码 | 当前行为 | 需要改变 |
| --- | --- | --- |
| connect.ts::draftProblem | bridge-candidate 在 hasDeck/siteGate 时跳过地面段走廊检查；crossings 可整体关闭 | 按段结构检查，入口只豁免自身明确通道，不豁免坡度/其他障碍 |
| connect.ts::commitFixedLink | validate 回调直接返回 null | 固定路线仍通过同一候选校验与提交接口 |
| connect.ts::corridorFailure | 每4单位中心点采样，预留是圆，未使用道路宽度 | 宽路面包络与实际占地终筛；地形采样有误差和预算 |
| intent.ts::evaluateDemands | 维护最近路，并遇主网近路提前 break | 短期消除枚举顺序影响；最终用显式入口节点到主网路径 |
| cityPlan.ts | place/snap 在 buildSkeleton 之前；后续继续挪设施 | 从车站/体育场开始改为骨架之后联合落位 |
| assign.ts | runAssignment 未被生产调用 | 接入最小纵向切片，不以注册表或单测代替实现 |
| solve.ts | 有违例时全策略原地运行，最多3轮，无候选回滚 | 草稿补丁，安全与需求接受规则，结束诊断 |
| cityLayout.ts::growWithBuildings | 第一条宽路作主网，裁路后按端点对筛车流 | 共享主网锚点与需求规则，实际展示图重验 |
| cityLayout.ts 计划缓存 | seed/tier/海滨配置为键 | 加算法/物理声明版本，限制容量，失败不缓存为成功 |

设施检查的枚举顺序风险：若孤立近路先出现，best 可能阻止稍远但合格的主网路；主网路先出现又可能提前成功。
应加 roadEdges 顺序置换测试。短期按主网路集合独立计算最小距离，最终替换成实际入口路径。
离线拆边和宽度继承已修，保留回归，不再列为待修漏洞；多点折线拆分仍需显式支持或拒绝。

## 3. 分批实施

### A：收口安全检查（首要）

先在 connect.ts 抽出共享候选表示与纯验证入口：

```ts
type RouteCandidate = {
  id: string;
  segments: RouteSegment[]; // ground/bridge，显式宽度与几何
  joins: JoinOperation[];
};
type CandidateValidation =
  | { ok: true }
  | { ok: false; violations: CandidateViolation[] };
// 搜索与固定连接均调用；校验读取当前草稿及预留，无正式状态副作用。
```

第一小批统一入口、消除策略整体豁免；下一小批替换中心线/圆口径为完整道路包络与模型占地。
桥面跨水用桥规则，引道仍受坡度、支撑、障碍与合法路口检查。前滩地面不必满足建筑 buildable，
但须按明确道路可行条件验证，不能用 maxSlope=Infinity 或 siteGate 代替。
对允许立体跨越的段检查高度净空；信息不足时返回 unsupported，不能只关闭平面交叉检查。

搜索失败候选不修改正式图。选中的候选若提交终筛拒绝，在整图预算内尝试后续候选，记录终筛原因；
不能让第一个草案堵住其它合法候选，也不能无预算重复搜索。
输出：connect.ts + corridor/validation 模块；策略函数仅产生候选，commitFixedLink 也走验证。
门禁：无水陡坡桥策略、真实桥陡坡引道、siteGate 压其他建筑、固定路线冲突、宽道路侧缘压楼都不能通过。

### B：主网、需求与展示统一

由 skeleton 输出 civic 环路上真实且稳定的 primaryAnchorNodeId，component id 仅为图版本内的派生值。
intent 与 growWithBuildings 共用 componentOf/入口可达规则，禁止各自选“最近节点/第一条宽路”。
入口引用真实节点和 owner；沿海路接入不能仅靠坐标相距小于1，而须引用共享节点/边。

展示图仅从已验收完整规划边选取，保留活动街区与必要设施到主网的路径；不可达时报告原因。
车流用有序 edge id/方向和拆边映射重建，恢复路径按长度而非边数比较。
验证空城、单街区、稀疏两岸、密集、回放往返、道路枚举置换；同活动集合的展示图必须一致。

### C：后置选址纵向切片（不等完整寻路框架）

先保留核心/广场联合确定；将车站和体育场改为骨架道路之后落位。
为这两类接入真实局部 footprint、基础规则、入口和入口预留，候选同时试算接入路线。
复用已安全的地面道路，不先开发完整 collector 或全新街网生成器。

把 assignSite 接入生产：选址成功与入口补丁联合接受；失败换候选，不返回非法 nominal。
生成与重选使用同一指派器，逐类删除旧挪动遍。其余设施继续显式兼容路径，记录覆盖。
门禁：生产调用证据、旋转长条占地、入口被占、不可达道路、候选全拒及容量诚实；固定seed近景验收。
此批在A/B最小能力具备后立即做，不等通用A*改造和多层拓扑。

### D：事务求解与最终产物

旧修复策略先在隔离草稿执行，提交前比较稳定对象的安全违例和需求向量。
安全为零后不得新增安全问题，已满足的必要需求不得被破坏；需求改善优先于软分。
旧草稿不安全时只允许减少旧问题且不新增/加重问题，不将非法草稿 finalize 为成功。

网络、设施、入口与预留一并提交。所有修复结束后生成地块、容量、车流和装饰；
不能靠过滤建筑掩盖容量不足。重建/取消后的错误传播覆盖 layoutCity → CityEngine → CityExperience。
门禁：撤销无副作用、策略互相抵消、桥头路被删、设施换位共享边、断头净增和未收敛有显式诊断。
收回 verify-city-solve 的断头+1过渡松弛时，以明确接受规则为依据，不仅调整测试数字。

### E：测量后优化性能与半径

在行为批之前加可关闭的阶段统计；E批根据累计证据优化，而非最后才开始测量。
记录候选数、拒绝原因、草稿克隆量、A*扩展数、整图累计预算、各阶段p50/p95与峰值内存。
预算跨设施、连接请求与半径重试累计；UI取消与工作批次让出执行权不影响确定性。

先复用道路空间索引及分量结果，按版本失效；草稿克隆按测量决定是否做局部copy-on-write，
不先构建复杂持久化图。拆分connect.ts中的搜索、桥候选、路口形态与验证，避免单文件继续膨胀。
分模块不能再次复制判据，消除底层模块反向运行时依赖cityPlan.ts。

半径记录每轮seed/tier/radius/raw/final容量和原因，先判断容量离散跳变，再选择有界夹逼等方法。
2.4倍容量旧记录仅是待查线索，不假定全部种子都过冲。半径变化须重验选址和路网。

## 4. 防过拟合与合并标准

- 已知缺陷种子作回归集；另固定未参与阈值调参的验收集，包含各tier、无河、宽河、陡岸和稀疏活动。
- 规则以道路宽度、入口和结构能力为依据，不加入seed条件。阈值改动说明来源，并报告独立样本变化。
- 合成已知答案与变换测试检查平移、旋转、道路端点反转、边枚举顺序及重复生成。
- 分开统计完整规划和展示图的安全、必要需求、合法降级及生成失败，失败岛不从分母移除。
- 影子指标、已修复fixture门禁与普查门禁分阶段推进，不能靠扩大上限把新安全问题变绿。
- 纯抽取保持baseline；行为变更审查差异后更新。相关检查包含typecheck/build、connect、network-patch、
  intent、footprint-geoms、sitespec、solve、survey、layout、规划/场景基线及cross-engine。
- 截图绑定commit/diff、seed/tier/config、活动集合和相机；测试通过不等同于视觉完成。

优先交付A的安全收口、B的最小主网/入口接口与C的两类设施接线。
完整意图生成器、张量场、地形重塑与统一立体路图继续后置；现有路口形态不得作为安全或连通证明。

## 5. 测试验证提速方案

补充日期：2026-10-09。以下为待实施方案，不表示测试入口或缓存已接线。
优先缩短日常反馈，再减少完整验收的重复计算；不通过减少最终安全覆盖换速度。
此前120岛普查超过四分钟是一次运行记录，未作同设备、同版本基准，不能作为当前性能定论。

### 5.1 分层运行与受影响范围

| 层级 | 建议入口 | 运行时机与内容 |
| --- | --- | --- |
| 快速 | verify:city:fast | 每次修改：typecheck、受影响合成测试、固定缺陷种子，失败即反馈 |
| 模块回归 | verify:city:module | 功能批完成：相关守卫与小规模跨档真实岛屿，检查生产调用和消费者 |
| 完整验收 | verify:city:full | 合并前：完整普查、规划/场景基线、跨引擎、布局/展示及构建；保留既有verify:city完整语义 |

入口命名为建议，实施时统一接入现有 package scripts。模块选择使用显式依赖清单：

- network 改动先跑 network-patch/connect，随后覆盖拆边、车流和布局消费者。
- footprint/SiteSpec/assign 改动覆盖几何、选址、模型一致性、布局与容量。
- skeleton/连接/solve 改动覆盖 intent、规划、求解、跨档普查与桥头关系。
- growWithBuildings/车流改动覆盖活动图、展示可达、布局和场景基线。
- 共享数学、模块加载器或测试基础设施变更，以及无法确定影响范围时，运行完整验收。

快速检查通过不宣称完整验收通过。无新改动、失败或未解决风险时，不反复重跑已通过的完整套件。
合并验收绑定实际代码指纹；新改动使受影响结果失效，不能复用先前版本的“全绿”记录。

### 5.2 共享规划结果与安全缓存

先测量 scripts/city-kit 的现有复用范围，再选择统一运行器：多个只读守卫在同一进程复用
同 seed/tier/config/skipSolve 的规划对象，减少模块重复加载和同岛重复生成。
会修改规划的测试取得副本；专门保留共享对象未被污染的测试。

缓存键必须包含生成器的传递源码依赖内容指纹（含未提交代码）、参数、算法/模型声明版本、
加载器及相关运行环境版本。只用分支名、commit 或seed不足以保证正确失效。
缓存只存计算产物；约束、评分与断言每次仍执行。若缓存断言结果，则还须绑定检查器代码与期望基线指纹，
首批不采用此模式。失败与取消不得写成成功结果。

Geography/plan 含函数闭包，不能直接用 JSON/structuredClone 假装完整持久化。
首批优先进程内复用；跨进程缓存需要显式可序列化快照及同版本查询重建，并验证冷热结果一致。
缓存有数量/内存上限。跨引擎测试按实际运行引擎独立生成，重复生成确定性测试绕过缓存，
不能拿同一缓存对象自比较作为确定性证据。定期无缓存完整运行验证缓存没有掩盖缺陷。

### 5.3 有限并行与性能记录

先并行独立测试组，再评估普查按seed分片；采用固定低并发并测量总耗时和峰值内存，
不默认把所有CPU核占满。并行任务使用独立临时输出，不并发写golden；汇总按tier/seed稳定排序。
复用与分片一起设计，避免每个worker重复生成全部岛屿；运行器等待全部任务结束并保留每项退出状态。

报告至少包括：设备/引擎版本、冷/热与缓存模式、总墙钟时间、脚本耗时、实际规划生成次数、
缓存命中率、最慢seed、半径重试、A*扩展量、峰值内存和检查覆盖。
日志及时显示已完成阶段，区分“仍在普查”与无响应；耗时只影响调度，不影响规划结果。

### 5.4 实施顺序与验收

1. 加脚本/阶段计时与生成计数，建立当前完整套件基准；不先改验证逻辑。
2. 接入fast/module/full入口与影响清单，保持完整验收覆盖不缩水。
3. 引入进程内只读复用，测试修改隔离、缓存失效及无缓存/复用结果等价。
4. 测量后启用有限并行；若重复生成仍为主要成本，再设计跨进程缓存。

验收同时比较新旧完整套件的测试集合、退出结果、违例集合、基线哈希与生成次数。
源码、配置、skipSolve、模型声明或检查器改变时必须正确失效；故障注入要被缓存/并行路径同样发现。
至少一次无缓存完整验收，确认跨引擎与确定性检查未被复用短路。
提速目标在基准建立后制定，交付报告实测比例；不提前承诺固定倍数。
