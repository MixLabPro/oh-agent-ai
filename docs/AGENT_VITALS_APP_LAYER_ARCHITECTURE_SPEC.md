# Agent Vitals 应用分层架构：以 Agent City 插件 APP 跑通首个闭环

版本：v0.2（重写设计稿，实施前冻结契约） · 日期：2026-10-03
关联：AGENT_VITALS_EXTENSION_ARCHITECTURE_SPEC.md、EXTENSION_ARCHITECTURE_IMPLEMENTATION_PLAN.md、
CITY_PLANNING_SPEC.md、RUNTIME_INVALIDATION_AND_READ_BACKPRESSURE_SPEC.md。

## §0 首个交付目标与完成定义

首个项目就是 Agent City 插件 APP。用户能够从 Agent Vitals 的应用管理入口安装 City、
授权取数、打开独立窗口、使用真实本机数据、更新 City、回滚、停用、卸载和重新安装。
City 的代码与素材能够独立发布；正常兼容更新不要求重新发布 Agent Vitals 宿主。

本规格中的“插件 APP”是独立版本、独立安装记录、独立进程和独立生命周期的应用。
首期选择官方签名的原生应用包：City 继续使用现有 React + Three.js，封装为独立
Tauri 应用。宿主主 WebView 不加载下载的 City JS；City 在自己的进程和 WebView 中运行。
只有移动目录、注册一个内置路由、展示 mock 数据或更换皮肤，都不构成首个闭环完成。

发布验收必须固定一个宿主构建 H，验证 City C1 安装运行 → C2 独立更新 →
C1 显式回滚 → 卸载 → 再安装；H 的构建标识全程不变，并有真实数据和实际分发物证据。
社区作者、通用市场、第二个应用、多引擎和独立皮肤市场均后置。

本文定义目标设计，不代表代码、发布渠道或权限策略已实现。实施证据只记在对应台账。

## §1 已有基础与迁移边界

现有 City 位于 apps/desktop/ui-dev/react/src/features/city/。cityData.ts 从
sessions/findings/统计时区取数，cityModel.ts 在 TS 中构建运行时模型，
CityEngine 消费模型渲染。CityModel.rows 是 Map，不能直接作为 JSON 传输契约。
种子读取当前可能初始化文件，set/reset 是写操作，不能混入只读投影。

迁移保留已有城市规划、时间回放、异常标记、会话钻取、种子稳定性、截图和电影导出。
既有行为的保留与新的隐私裁剪分别记录；必要的裁剪须在验收中解释，不能以
“presentation 不参与 parity”为理由取消统计语义或城市行为验证。

扩展项目已有 revision/generation、不可变对象、预览确认、目录下载及发布检查的基础。
这些用于复用生命周期设计和校验原语；现有对象存储只接收 JSON payload.json，
不能直接用于安装可执行 .app 包。宿主 DSL 和所有数据插槽完成不是 City 首发前置条件。

## §2 架构与责任

~~~text
Agent Vitals 宿主进程
  ├─ 工作台：overview / sessions / findings / settings 等现有数据面
  ├─ 应用管理器：目录、签名、安装台账、授权、启动、更新、回滚、卸载
  └─ App Broker：握手、能力协商、投影读取、事件通知、受限控制
       └─ 查询服务：版本化投影 + face transformer + ReadGate + memo
            └─ 现有 authority / query / ingest（事实与计费规则）

已安装 Agent City 独立应用进程
  ├─ 原生桥：本机 IPC、会话授权、宿主状态、导出文件选择
  ├─ SDK：投影类型、协商、分页、失效事件、错误语义
  └─ React / TS 模型与规划 / Three.js 渲染 / 内置默认素材
~~~

查询层不知道 City 的窗口或渲染引擎。应用管理器维护安装与授权记录，
不把应用注册表放入查询层。新应用只声明已有能力即可消费已有投影；
新增领域数据能力仍可能需要增加投影，不能承诺任意新应用都零后端工作。

投影实现放在 agent-vitals-query；broker、安装与进程编排放在 runtime/宿主适配层。
OS 签名检查、进程身份、LaunchServices 和文件选择属于平台适配器。
第一期 macOS；Linux/Windows 的 IPC、签名和打包适配明确列为后续任务。

## §3 插件应用契约

### 3.1 Manifest

app-manifest-v1.json 是应用包元数据的单一真源，至少包含：

| 字段 | 规则 |
| --- | --- |
| manifest_version、id、version | schema 版本；稳定 id 如 agent-city；应用版本使用发布 SemVer |
| publisher、signing_key_id | 展示信息；实际发布者来自宿主信任根和验证结果，不能靠自报授信 |
| platform、architecture | 精确匹配可运行平台/架构；不适配则拒绝启动 |
| entry | 平台包内受验证入口；禁止任意绝对路径、shell 字符串和目录外入口 |
| host_compatibility | 支持的宿主发布版本范围及 broker 协议版本集合 |
| requires | projection id、明确支持的版本集合、face、必需/可选标记 |
| permissions | 允许的查询投影、控制操作、导出用途；默认零数据权限 |
| state_schema_version | 应用私有状态版本和可回滚迁移规则 |
| resources、licenses | 文件清单、逐文件哈希、大小、素材许可及预算 |
| display | 名称、图标、说明；不决定权限或来源 |

例如 City 声明支持 city:v1 的 app-local face、失效事件、宿主打开会话控制，
而不是“可以调用全部 Tauri command”。projection 版本是精确支持集合，
应用版本与投影版本互相独立。宿主选择双方共有的最高明确支持版本；
没有交集或必需权限未授权时拒绝挂载，列出缺失项。可选项只按声明降级。

### 3.2 三类分发物

| 分发物 | 是否含执行代码 | 安装与信任规则 |
| --- | --- | --- |
| plugin_app | 是；首期为官方签名 City .app | 独立 app index、包签名、平台签名、显式安装授权 |
| content_pack | 否；主题/植被/角色/特效 | 纯装饰数据、安全格式剖面、内容台账；后续接入 |
| host_manifest 等数据扩展 | 否 | 沿用扩展规格的数据插槽规则 |

应用包不得伪装为 content_pack 或 host_manifest；数据扩展安装器不能执行它。
第一期 City 默认素材随应用包发布，足够验证完整闭环；无需等待内容市场上线。
社区应用需要额外的发布者信任、进程限制和数据披露政策，首期不开放。

## §4 数据契约：先拆 DTO，再保留运行时模型

### 4.1 CityDataProjectionV1

city:v1 返回渲染所需的可序列化输入，不返回现有 CityModel 本身。最低数据组成：

| 数据 | 内容与约束 |
| --- | --- |
| window | 起止时间、统计时区、as_of_ms；由宿主明确给出，禁止客户端隐式改口径 |
| sessions | 应用作用域 opaque id、host、事件时间、token 统计和可靠性标记；分页有硬上限 |
| host_summaries | 已有宿主显示信息、窗口统计、脱敏异常分类/数量/严重性 |
| coverage | 全窗真实总数、已返回数、分页/截断/缺失/时间未知状态 |
| snapshot | 数据 revision、快照 id、过期时间；分页与后续补抓必须声明一致性 |
| freshness | 更新中、过期、未同步或可用；不可把读取失败显示为真实零用量 |

不返回宿主日志路径、原始会话锚点、标题/提示词、工作目录、错误原文、调用参数、
credential 或 canary。app-local 允许逐会话统计摘要，因此不称其为“纯聚合”；
它比未来 aggregate 面更细，必须有独立 schema 和显式权限。

CityRuntimeModel 仍在应用 TS 中构建，Map、楼宇索引、L1–L4 规划与动画状态留在应用。
opaque id 在同一应用安装身份下稳定；撤销/卸载失效后的 id 不授予任何新访问权。
原始 SessionRow 钻取索引由宿主持有，City 只发送受限句柄，请求宿主打开数据面。

### 4.2 查询、状态和控制分开

projection.read 是只读。City 的种子、镜头、时间窗偏好存入应用私有状态；
迁移旧 seed 时由宿主显式导出并记录，City 不读宿主 state 文件。
set/reset seed 是应用自身控制，不是查询副作用。

app.open_session 仅接受授权作用域内的 opaque 句柄；用户操作触发宿主展示，
不向 City 返回原始片段。不存在任意文件读取、SQL、字段选择或通用命令代理。
截图/电影由 City 在本机生成，用户通过文件选择器决定导出位置；不自动上传。
卸载保留已导出的用户文件。

### 4.3 Schema 与兼容性

每个 (projection id, version, face) 有请求/响应 schema、限制、错误和 fixture。
schema 放在 docs/schemas/；TS 类型生成并提交；Rust 通过类型约束及输出实例校验。
有意新增 optional 字段须通过兼容性检查并审核更新 golden；删除字段、改变类型、
收紧枚举或增加 required 字段属于破坏变更，发布新版本。codegen 漂移检查不能替代
schema compatibility 检查；二者均接入 CI。固定 as_of_ms、排序及 JSON 字段规则，
以可复现输入验证 City 模型，动态生产时间不直接参与字节 golden。

能力注册表从同一投影元数据生成；不得另维护一份恒通过的前端能力表。
有兼容客户端时保留旧版投影；撤下旧版前记录已安装应用影响并明确阻止不兼容升级。

## §5 服务面与读服务拓扑

| 面 | 消费者 | 允许数据 |
| --- | --- | --- |
| app-internal | 宿主自己的工作台 | 现有按功能定义的数据；仍遵守 serving-face 规则 |
| app-local | 首期已授权、签名验证的 City 独立进程 | city:v1 会话统计摘要、作用域句柄；无原始锚点 |
| aggregate-local | 后续本地应用 | 逐投影明确开放的聚合；首期默认关闭 |
| mcp | 现有 agent | 保持现有 redacted 契约；不暴露应用包、授权 token 或 canary |

macOS App Broker 使用用户私有目录中的 Unix socket，不提供 HTTP 监听或公网入口。
City 本机桥连接 broker；WebView 只能调用自身有限原生桥，不能 invoke 宿主命令。

宿主工作台与 City 请求在同一个宿主查询进程内共享 ReadGate 和 memo。
现有 data-mcp 是独立进程，只共享查询实现、schema/失效规则，各自拥有进程内闸门和
缓存；首期不宣称跨进程全局两许可。若未来统一所有服务到 daemon，另设迁移任务。

服务面裁剪先于面向客户端缓存，缓存键至少含 projection/version/face、规范化参数、
数据 revision、授权策略版本和数据范围；不得把 app-internal 缓存直接返回 app-local。
内部纯计算可以另设受保护缓存，但每次响应仍需执行 face 与授权检查。

首期宿主重查询并发沿用 2；每个应用最多 1 个在执行重请求，有限 FIFO 队列、
超时/取消和忙碌错误，不允许单应用占满队列。分页用 snapshot cursor；
底层无法维持快照时必须返回 snapshot_expired 并重读，不静默拼接多个 revision。
revision 事件只通知失效，不携带用户数据；有序号、重连补读、订阅数与队列上限。

## §6 授权、启动与进程约束

安装前展示验证过的发布者、版本、磁盘预算和读取字段/操作；用户明确允许。
安装许可、数据许可和联网下载许可分别记录。授权记录绑定 app id、验证发布者、
权限集合与策略版本；应用升级不能自动扩权。

启动由宿主应用管理器执行，macOS 通过已验证 .app 的系统应用启动路径。
不从 shell 拼接命令，不运行宿主菜单栏裸二进制。固定入口、私有工作目录和环境白名单；
应用不能直接获取 authority 路径、宿主日志根目录或 cc-switch/主机 credential。

socket 目录 0700、socket 0600；握手校验同 UID、实际启动进程身份和平台代码签名。
同 UID、manifest id、自报 publisher 或 PID 字符串均不能独立授信；平台适配器必须
证明连接者是此次启动的允许应用实例。握手签发短期连接授权，只在内存中存在，
不放入 argv、日志、MCP、导出或自有磁盘文件。持久化记录仅含非秘密 grant 元数据。
平台身份校验不可用时拒绝生产数据连接；开发模式只接脱敏 fixture。

权限按每个请求与响应交付前复核；撤销先阻止新请求、取消排队/订阅，再使运行会话
失效。已经交付给应用的数据无法撤回，UI 不承诺清除其所有内存。
宿主退出/重启使授权会话全部失效；City 显示宿主离线，重连需重新握手。
停用/卸载清除进程与授权；进程崩溃不影响摄入，不无限自动重启。

独立进程和签名不等于文件系统或网络沙箱。生产包须提供平台可验证的最小权限配置：
禁止后台外网访问和任意宿主数据目录访问；WebView CSP 禁止远端脚本/连接；
原生桥没有通用 shell、文件或网络接口。仅有静态代码检查不能证明 OS 级限制。
macOS 沙箱与本机 IPC 可行性必须在首轮 spike 中实测；未通过前不可签发真实数据授权，
且不得降级为“签了名就可直接读库”的实现。用户选择的导出权限与任意文件权限分开。

## §7 应用包、目录与生命周期

### 7.1 分发契约

单独建立 app-index-v1.json；不向严格 catalog-index-v1 偷加未知字段。
每个 app index entry 固定 app id/version、平台/架构、不可变包 URL、包 SHA-256、
大小、manifest digest、权限摘要、发布序号、发布者 key id 和签名。
包签名覆盖明确的规范化发布清单；清单绑定每个文件的哈希、入口、权限与兼容范围。
目录本身也须签名，覆盖来源标识、单调发布序号、完整条目集合与信任元数据；
验证签名后才接受目录高水位，拒绝旧目录重放或未签名序号推进。
JSON 规范化、签名算法和密钥轮换/吊销格式在 C1 任务中冻结，测试不得各用一套约定。

首期采用 Ed25519 发布签名和宿主内置官方公钥，同时校验 macOS 包的代码签名与
发布 notarization。两种签名各有用途，不能互相替代。入口 .app 校验后在启动前再次
核对；未知/吊销 key、坏签名、包内容变化或不兼容平台一律拒绝。
开发包与正式包使用不同信任入口，开发入口默认关闭且不读取真实用户数据。

官方目录与包下载仅访问配置冻结的公共 HTTPS 来源；禁外部重定向，实际流式读取
执行限额。联网默认 opt-in，无日志、画像、机器 id、授权 token 或用户数据请求参数。
初始限制：index 4 MiB，归档 256 MiB，展开 1 GiB，最多 20,000 个文件，
安装目录总量 2 GiB（含回滚保留版本）；超限拒绝，不允许索引自报扩大宿主上限。
预检 available disk 并留 staging/回滚余量；下载失败不影响当前版本。

### 7.2 状态机与原子激活

~~~text
未安装 → staging → 校验完成 → 等待授权/确认 → installed → 启动 → running
running → 停用 → installed
installed/running → 新版 staging → 校验/权限比较 → 显式更新 → 新 active revision
新版本失败 → 明确提示 → 已验证旧版本恢复（生成新的 activation 记录）
installed/running → 显式卸载 → 未安装（历史安装/激活记录保留）
~~~

安装包在应用私有同文件系统 staging 中展开，拒绝绝对路径、路径穿越、符号链接/
硬链接越界、大小虚报及压缩炸弹；完整文件验证后发布到不可变 app object 目录。
不在宿主数据扩展对象目录存可执行包。authority 中独立应用表保存 revision、
active generation、授权策略版本与安装状态，复用事务/CAS机制但不混淆数据插槽。

预览绑定包哈希、manifest、权限差异、当前 app generation、兼容能力与状态迁移。
确认重新核对；并发变化使确认失效。对象先完整持久化，随后事务切指针。
更新先停止旧实例/撤销会话，再切换启动新实例；应用固定使用一个包 revision。
旧版本对象及状态快照保留至新版本健康检查成功，失败显式记录恢复旧版本；
健康检查成功后仍至少保留上一可回滚版本及兼容状态快照，计入磁盘预算。
回收不得删除 active 或承诺可回滚的对象；仅有历史台账不代表包仍可恢复。
崩溃后启动检查恢复可用 active，不能将半展开包当 installed。

只读 City 查询不会改写事实；应用回滚不回滚 authority 数据。
City 状态初期优先兼容加字段；破坏状态迁移必须备份并提供逆向/快照恢复，
无恢复方案则拒绝承诺该版本可回滚。用户可显式回滚已验证历史版本；
目录防降级高水位与用户主动应用回滚是两个独立状态，回滚不降低目录高水位。

卸载先停实例、撤授权和订阅，再切 active 状态；删除包与应用私有数据采用可恢复操作。
默认保留 seed/偏好与用户导出，用户可另选清除私有状态；历史台账无原始日志或秘密。
重装恢复兼容偏好，但重新授权。应用私有数据库和设置使用独立目录，不能访问 authority DB。

### 7.3 更新失败与来源呈现

分别展示 installed version、running revision、available version、授权范围和更新失败原因。
缓存目录、用户路径、自报 origin 均不能成为官方来源证据。
离线时现有已验证 City 可启动/取数/导出/回滚；下载与检查远端更新需要联网。
离线导入完整签名包仍须通过同样的信任、兼容、预算和授权门，不绕过目录防重放策略。
检查更新不自动安装，不自动解钉或扩权；新增权限拒绝后旧版本继续可用。
签名信任策略撤销后的版本不得继续获得新会话；离线按最后有效本地信任状态执法，
不承诺在无联网时获知新的远端吊销。

## §8 内容、规划与引擎

City 的规划/模型在无头 TS 层，Three.js 只渲染；保留确定性守卫。
首发默认素材许可齐全，加载失败退回程序化呈现，不能让统计或交互失效。
内容包将来独立更新时复用 app 使用的素材 schema/加载器；参数允许列表只控制视觉，
不能改统计、计费、行为资格、可拾取性或权限。付费仅装饰，数据能力无付费墙。

后续 GLB/VRM/KTX2 包须限定 format/extensions、magic、文件数、解码后纹理/几何预算，
禁止网络 URI、绝对路径和外部资源；JSON 参数无表达式或脚本。
content_pack 多文件对象契约和 catalog index 新版本另行冻结，旧 v1继续可用。
社区签名、多来源 index、支付、开发者市场、bevy/Unity/Godot 均为后续能力，
不作为 City 插件 APP 完成的替代品或前置依赖。

## §10 验收门

| 编号 | 场景 | 必须证据 |
| --- | --- | --- |
| G01 | 契约与协商 | schema/实例/codegen/兼容性CI；未知能力/版本无交集拒绝 |

| G05 | 数据面隔离 | 无原始锚点/错误/参数/秘密；跨face缓存污染和越权句柄拒绝 |
| G06 | 读服务 | 宿主+City共享并发上限、每app限额、取消/超时、失效/快照过期 |
| G07 | 进程与权限 | 实际 .app 启动、假冒连接拒绝、沙箱/联网/目录访问限制实测 |
| G08 | 生命周期 | 撤销/停用/宿主离线/City崩溃；不影响摄入，重连重新授权 |

文档评审、fixture安装、独立窗口截图或一次成功启动不能替代整套验收。
