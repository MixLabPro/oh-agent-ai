# Claude Code 会话语料快照(实测)

> 采集日期:2026-09-01。源:本地 `~/.claude/projects` 全部项目会话 JSONL。
> 观测单位 = 一条 `assistant` 事件(请求)。**所有数字是聚合,不含任何原始行、路径或会话标识。**
>
> 关联:[COST_BASELINE.md](./COST_BASELINE.md)(Codex/DSH 基线方法与语料期纪律)· [ATTRIBUTABLE_WASTE.md](./ATTRIBUTABLE_WASTE.md)(W1 定义,本文的判定依据)。
>
> **用前必读**:Claude Code 一个会话可路由到 **4 个模型家族**,每个家族是**独立的缓存宇宙**——跨家族命中率不可通约、不可相加。下文全部按家族分栏。

文件主导家族:deepseek ×53、claude ×48、**混家族 ×18**、minimax ×7、synthetic ×4。14% 的文件在会话内切换模型。

## 2. 缓存机制跨家族结构(本语料的核心结构事实)

| 家族 | 缓存形态 | 证据 |
|---|---|---|
| claude | Anthropic prompt caching | `cache_creation` 每请求写增量、`cache_read` 单调追前缀,命中率 100.0% |
| deepseek | **DeepSeek 自动前缀缓存**(不计量、不收费写缓存) | `cache_creation` **恒 0 是设计语义,不是缺失**——与 DSH 侧 deepseek `cache_write=0` 同一物理,两宿主已对齐;`cache_read` 单调增长(下 §3 证真) |
| minimax | 有缓存字段,命中率 87.3% | 唯一低于 W1 阈值的家族(§4) |
| kimi | 9 请求、命中率 1.0% | moonshot 不提供同语义前缀缓存(§4 不归因) |

**跨家族缓存不可共享**:「claude 的缓存被 deepseek 顶掉」在物理上不存在——换模型即换缓存宇宙。混家族(18/130 文件)是**结构性事实**,不是可归因浪费。

## 3. deepseek cache_read 真实性核验(定案)

`cache_read` 一度是最大疑点(DSH 侧 deepseek cache_write=0,故怀疑 Claude Code 侧 32 亿 cache_read 是字段语义造假)。逐请求时序核验后**证真**:

- 19 个 deepseek-v4-flash 会话采样 4,176 请求:**17/19 严格单调**——`cache_read` 追会话累积前缀增长,`input_tokens` 随之前缩(34K → 3.4K → 1.5K → 185),这是适配器 mis-fill 造不出来的形状。
- **9/19 首请求 `cache_read=0`**(冷启动签名)。
- 2 个含回退的会话回退次数极少(314/400 请求内 1–2 次),符合缓存驱逐/切换。

结论:**deepseek 的 cache_read 是真前缀缓存**,可进 waste 数学。

## 5. W1 浪费信号(判定依据:`ATTRIBUTABLE_WASTE.md` §2-W1)

- **minimax 命中率 87.3% < 90% 阈值 —— 本语料唯一触发 W1 的家族**。2,958 请求、5,130 万未缓存 input、集中在 12 个文件。已下钻定案(2026-09-01):
  - **文件 #19 独占 minimax 未缓存 input 的 72%**(36.75M/51.3M),命中率 55.4% —— W1 的可复核目标即此文件。
  - #19 的病理**不是模型抖动**(1,669 事件仅 12 次切换,minimax 连续段 391/263/79):733 个 minimax 请求中 **376 个(51%)input>15K**(最大 51K),而全冷写仅 8 个(1%)。缓存在其内仍工作(最大 cr=153K)——是**前缀反复被打破**,不是缓存不可用。对照 #21(97.5%,1,104 请求)仅 9% 大 input,MiniMax 缓存能力无问题,**#19 是会话形态问题**。
  - 三个纯子代理文件(#53/#50/#52)命中率 65–85% 系**子代理生僻缓存冷启动**,体积微小,不追。
  - 按 W1 纪律只 flag、不扣减;复核时先看 #19。
- **kimi 命中率 1.0% —— 不归因**:9 个请求、模型无同语义前缀缓存,「可缓存前缀被浪费」的前提不成立。
- **claude / deepseek —— 健康,无 W1 信号**。deepseek 的 9,120 万未缓存 input 是**全语料最大 uncached 单块**,但 97.3% 高于阈值,按 W1 定义不归因(其 miss 价 ≈ hit 价 10× 的放大效应只影响钱、不影响 token 判定;钱见 §6)。

## 6. 诚实性注记

- **全部 token-only,不报钱**:claude/minimax/kimi 三族在仓库内无定价来源,只给 deepseek 计价会得到半张账单——违反「缺列不编列」。要出钱,先要有这四个家族的 2026-09 价格表。
- **无日期分界**:本语料未按时间切「bug 期/稳态期」(对照 COST_BASELINE 的 DSH 08-18 分界),无法做前后对照,不编。
- **混家族 18 文件是结构事实,非浪费**:不同模型无法共享前缀缓存,计数不合并。
- **未做因果推断**:minimax 命中率偏低是观察,不是「缓存坏了」的结论。
- `<synthetic>` 事件零 token,已排除;其存在本身是合成/后台事件占位,不含模型用量。
