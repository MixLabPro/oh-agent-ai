# 城市地图编辑器路线图（按优先级）

> 状态：草案（2026-10-12）。分支 `worktree-city-plan-repair`。
> 上游：`CITY_PLAN_MANUAL_REPAIR_SPEC.md`（编辑器现状，§13–§17）、`CITY_SITE_REGISTRY_SPEC.md`（对象注册表 B0–B4）。
> 两层架构不变：city-opt 是**默认地图生成器**，本分支是**用户地图编辑器**；编辑器只读生成器的导出，不改生成器文件
> （需要生成器改动的条目单列为「前置」，由 city-opt 线自决）。

## 0. 排序依据

1. **会不会让用户丢东西或用不了**——先修。main 已把默认时间窗从 30 天改为 366 天（`7f1938ec`），
   真实用户的城市会接近最大档（4000 栋），而编辑器只在 ≤ 380 栋上验证过交互。
2. **编辑能力缺口的频度**——用户已经点名的（改路型、过河、转角）优先于没提过的（景观、框选）。
3. **工程成本**——同档里先做小的。

| 优先级 | 编号 | 一句话 | 规模 | 前置 |
| --- | --- | --- | --- | --- |
| **P0** | 1 | 大城市性能：悬停零卡顿、提交不全量重排 | 中 | 无 |
| **P0** | 2 | 扩档不丢修改：补丁随城市放大重定位 | 中 | 无（补丁 v2 锚点） |
| P1 | 3 | 设施落位走生成器判定（注册表 B3） | 小 | city-opt 已导出 `checkSitePlacement` ✅ |
| P1 | 4 | 改已有道路的路型 | 小 | 无 |
| P1 | 5 | 地面桥：地面路过河 | 中 | 渲染层认补丁生成的桥（需确认，见 §5.4） |
| P2 | 6 | 高架匝道接地面路（车流上高架） | 中 | 生成器车流路径导出（需 city-opt 配合） |
| P2 | 7 | 框选与批量操作 | 中 | P0-1（批量推平会放大性能问题） |
| P2 | 8 | 景观工具（树/公园/景观湖） | 中 | 注册表 B1（名称）、P1-3 |
| P3 | 9 | 撤销历史持久化 | 小 | 无 |
| P3 | 10 | 地图修改导入/导出 | 小 | P0-2（导入别的档位的补丁要重定位） |
| P3 | 11 | 端到端交互回归测试 | 小 | 无（越早越好，可与 P0 并行） |
| P3 | 12 | 产品化：去开发开关、中英文、小窗口、新手引导 | 中 | P0 全部 |

## P0-1 大城市性能

### 1.1 实测（`scripts/bench-plan-editor.mjs`，2026-10-12，M 系列 Mac，node 22）

366 天窗口、合成会话数据，同一机器同一次运行：

| 操作（毫秒） | 380 楼 · 1 档 | 1600 楼 · 4 档 | 4000 楼 · 10 档 | 触发时机 |
| --- | --- | --- | --- | --- |
| 生成器出图（参考，生成器的事） | 13 451 | 29 710 | 64 384 | 数据刷新/换种子 |
| `layoutCity`（命中规划缓存） | 78 | 466 | **1 322** | **每次编辑提交**（见 1.2） |
| `applyPlanPatch`（一条画路） | 2.5 | 3.9 | 6.8 | 每次提交 |
| `validateRoadAdd` | 1.0 | 0.7 | 1.6 | 画路悬停 |
| `validateEdgeDrop` | 18 | 150 | **727** | **橡皮擦悬停** |
| `validateNodeMove` | 0.4 | 1.7 | 2.3 | 拖路口悬停 |
| `bulldozeForRoads`（试算一笔穿楼的路） | 229 | 309 | **8 858** | **画路/拖路口悬停**（有推平/安置时） |
| 选中会话楼的 40 个候选地块 | 26 | 86 | **331** | 选中 |
| `auditLayout` | 66 | 664 | **3 602** | 点「体检」 |
| `snapPoint` / `nearestEdgeAt` / `pickSite` | ≤ 0.6 | ≤ 0.6 | ≤ 0.6 | 悬停 |

规模：4000 楼时 2402 路段、1533 路口、8815 地块、332 处设施。

### 1.2 问题

- **悬停卡死**：4000 楼时画一条穿楼的路，悬停试算要 8.9 秒（推土机安置 4 栋会话楼）；橡皮擦每移一下 0.7 秒。
  §16.2 把预览改成推土机试算是对的（预览与结果一致），但没在大城市上测过。
- **每次提交都全量重排**：`CityEngine.setPlanPatch` → `applyModel` → `layoutCity`。道路/设施编辑根本不需要重排
  （`layoutCity` 只为移楼的 pins 存在），却每次付 1.3 秒，再加场景重建（未测，见 1.4 第 1 步）。
- **体检 3.6 秒**：按需触发、可接受但不舒服；提交后面板开着时会自动重跑，等于每次编辑多 3.6 秒。

### 1.3 设计

预算（4000 楼）：**悬停 ≤ 16 ms**（一帧）、**选中 ≤ 50 ms**、**提交 ≤ 300 ms**（不含场景重建）、**体检 ≤ 300 ms**。

1. **提交分级**（CityEngine）：补丁变化只涉及 `roadOps/highwayOps/siteOps/suppressedContext` 时，直接在缓存的
   `baseLayout` 上重套补丁（7 ms），不调 `layoutCity`；只有 `buildingMoves` 增删才走 `layoutCity`（pins 必须在落位阶段生效）。
   需要确认的不变量：没有 buildingMoves 变化时，`layoutCity(model, previous)` 与缓存的 `baseLayout` 相同——守卫断言之。
2. **空间索引**：规则层现在逐条扫全城路段/地块/障碍。加一个随布局对象缓存的网格索引（WeakMap，按布局回收，同 `obstacles()` 的做法），
   给 `rectClearOfEdges`、`reservedParcelIds` 的命中查询、`validateBuildingMove`、`edgeAt`、`hitsBy` 用。
   `planner/` 里已有 `SegmentIndex`，优先复用（只读导入，不改它）。
3. **推土机**：安置循环里每安置一栋就全量 `applyPlanPatch` + 从近到远对每块地完整校验。改为：一次算出占用集合，
   候选先用 O(1) 的「地块被占？」筛掉，再做完整校验；安置后增量更新占用集合，不重套补丁；最后只套一次补丁验证。
4. **悬停降级**：试算超过 16 ms 的，悬停时先给 `roadImpact` 的估计（已有，琥珀色 + 「约」字），鼠标停住 150 ms 后再跑精确试算并替换；
   提交永远跑精确的。预览与结果「一致」的承诺改为「停住后一致」，并在面板上区分「估计」与「确切」。
5. **橡皮擦**：`validateEdgeDrop` 的「楼会不会失去道路/断网」是全城连通性检查。改为只检查被擦路段两端各 N 跳内的局部连通性
   （删一条边只可能把与它相邻的部分切开），全城检查留到提交时。
6. **体检**：同样走空间索引；面板开着时提交后**不自动全量重跑**，只标「可能已过期，点刷新」。

### 1.4 步骤与验收

1. 先补测场景重建：在浏览器里测 4000 楼一次编辑的「提交 → 可交互」总时长（`performance.mark`），拆成 补丁/重排/场景 三段。
2. 1.3-1（提交分级）→ 1.3-2（索引）→ 1.3-3（推土机）→ 1.3-5 → 1.3-4 → 1.3-6，每步跑 `bench-plan-editor.mjs` 记一行数。
3. 验收：4000 楼下上表加粗各项达到 1.3 的预算；`verify-plan-*` 全绿；索引前后所有校验结果逐字相同（守卫：在真实城市上对 200 个随机操作比对新旧实现）。

## P0-2 扩档不丢修改

### 2.1 问题

`scaleTierFor = ceil(会话数 / 400)`。会话数跨过 400 的倍数，城市升档：岛按原形状放大、地块与路口全部重排。补丁记着自己写在哪一档，
档位不符就**整份作废**（`tier-changed`，§16.5 只做了横幅提示和一键清除）。366 天窗口下，活跃用户每隔几周就会跨档一次——
用户的感受是「我改好的地图过几天全没了」。

生成器对会话楼已经做了跨档迁移（`cityLayout.ts`：按 `新岛半径 / 旧岛半径` 把每栋楼映射到放大后原位置附近的空地块），编辑器的补丁应同样处理。

### 2.2 设计：补丁 v2，每条操作带锚点坐标

重定位需要知道每条操作「当时在哪里」。现状：
- 道路 add/move、高架、自由级设施搬家的目标本身就是坐标——可直接缩放；
- 路段 drop、路口 move 引用的 id 由坐标派生（`x:z`、`from/to`）——可解析出坐标；
- 设施操作带 `at`；街区/地块目标 id 里有面多边形坐标——能解析但脆弱；
- `buildingMoves` 只存目标地块 id。

**v2**：`PlanPatchV2` 给每条引用型操作加 `anchor: Vec2`（写入时记下被引用对象的中心），`buildingMoves` 改为
`{ parcel: string; anchor: Vec2 }`。读 v1 存档时一次性迁移：能从 id 解析出坐标的补 anchor，解析不了的保留原样（只能同档使用）。

**重定位**（`remapPlanPatch(patch, fromTier, toTier, ratio, layout)`，纯函数）：

| 操作 | 规则 |
| --- | --- |
| 画路 / 高架 / 自由级搬家目标 | 坐标 × ratio，照常重放 |
| 删路段 / 拖路口 / 切高架 | anchor × ratio 后找最近的同类对象，容差 `6 × ratio`；找不到 → 单条 `remap-failed` |
| 设施拆除 / 搬家 | `at` × ratio 后找最近的同类设施（同 kind），容差同上；街区/地块目标按 anchor × ratio 找最近的合法目标 |
| 移楼 | anchor × ratio 找最近的空地块（与生成器迁移同一规则）；找不到 → 单条失效，楼按常规落位 |

- 重定位结果**作为新的一版补丁提交**（可撤销），原补丁归档到存档的 `history[tier]`（每档留一份），用户可以在面板上「恢复旧档修改」比较。
- 面板：横幅改为「城市扩大了一档，已为你的 N 处修改重新定位，M 处没找到对应位置（查看）」。失效条目在体检里逐条列出并能定位。
- 不承诺跨档后一模一样：新档的路网是生成器重新长出来的，用户画的路会接到新路网上，结果可能与原意略有出入——这是如实的代价。

### 2.3 验收

- 守卫：真实城市 380 → 420 楼（1 → 2 档）、1600 → 2000（4 → 5 档）各造 30 条混合操作的补丁，跨档后重定位成功率 ≥ 80%，
  失败条目都有 `remap-failed` 记录，补丁重放无其他失效；同档读写 v2 存档与 v1 行为一致；v1 → v2 迁移幂等。
- 降档（会话数减少）同样处理（ratio < 1）。

## P1-3 设施落位走生成器判定（注册表 B3）

city-opt 已导出 `checkSitePlacement`（`d500ffc7`）。按 `CITY_SITE_REGISTRY_SPEC.md` §5/§10 B3 实施：`planSites.siteMoveProblem`
的街区级/地块级判定改调生成器谓词，删掉编辑器自造的「整块空街区」近似与 `PICK_HEIGHT` 表；修 D1（城区地标搬到装不下包络的地方）、
D2（不规则街区里设施出界）。既有补丁里原本「合法」的少数搬家会被判失效，如实上报（注册表 SPEC §12-3）。小，建议紧跟 P0 做。

## P1-4 改已有道路的路型

现在只能擦掉重画。新操作 `roadOps: { t: "restyle"; edge: string; width?: 5|8|12; purpose?: "waterfront" | null }`：
- 橡皮擦旁加「改路」工具（或画路工具里点一条已有路）：悬停高亮整条路（`roadPaintPlan` 的 run，不是单个路段），点选后面板给路型按钮。
- 变宽会压到两侧的楼：走推土机（推平/安置），与画路同一套提示。
- 滨海景观带随 `purpose` 自动派生（§17.1 的 `deriveCoastRoads` 已支持）。
- 不能改：桥面（`edgeLocked`）。

## P1-5 地面桥

地面路过河仍是 `road-in-water`；高架能过河但不通车。设计：画路时线段穿过水面，若两岸都是陆地、水面段长度 ≤ 160，
自动把水面段生成为桥（`bridge: true, structure: "deck"`）、两端各一段引道（`structure: "ground-approach"`），与生成器的桥同构。
- **前置确认**：渲染层画桥面读的是 `roadEdges` 里 `bridge` 的路段（`roadSystem.ts:33`），桁架装饰读 `layout.bridges`。
  需确认补丁新增的 bridge 路段能被画出来、车流能走——若车流路径（`carPaths`）只来自生成器，需要 city-opt 导出车流派生函数。
- 规则：桥不能有路口（交叉自动生成路口时跳过桥段，已是现状）；桥长 > 160 拒绝；桥下净空（高架、航道）提示。

## P2-6 高架匝道接地面路

高架现在两端落地即止，不接路网，车流不上高架（生成器的高架也是）。若要「能走的高架」：高架端点吸附地面路口时生成一段匝道路段，
车流派生把高架纳入。**需要生成器的车流派生配合**，先与 city-opt 线对齐再排期。

## P2-7 框选与批量操作

框选（按住 Shift 拖矩形）选中区域内的设施/路段：批量拆除、批量擦路、「清场」（推平区域内所有非会话建筑，会话楼走安置）。
批量操作是一条复合补丁操作、一步撤销。依赖 P0-1：批量推平是性能最差的路径。

## P2-8 景观工具

种树（点/刷）、放公园、挖景观湖。新的补丁层 `landscapeOps`；树走现有 `parkTrees` 渲染，公园/湖作为新的自由级设施。
依赖注册表 B1（名称统一）与 P1-3（落位判定）。

## P3-9 撤销历史持久化

撤销栈只在内存里，刷新就没了。按种子存最近 50 步到存档（补丁本身已持久化，只多存历史）。

## P3-10 导入/导出

导出 JSON（补丁 + 种子 + 档位 + 版本）；导入时跨档走 P0-2 重定位，失效逐条报告。

## P3-11 端到端交互回归测试

现有测试覆盖到控制器（纯状态机）与规则层；画布上的拾取问题（拾取盒挡住空地、移动工具选不中细塔）都是手测发现的。
`scripts/verify-plan-repair-e2e.mjs`：用引擎级模拟点击（`pointer.set` + `handleClick`，本分支浏览器验证一直这么做）录
「选中 → 搬家 → 画路 → 拖路口 → 高架 → 撤销」，断言补丁与场景。需要无头 WebGL（playwright + chromium 或 node 的 headless-gl），
先评估 CI 可行性；不可行就作为本地脚本。

## P3-12 产品化

- 去掉开发开关 `?cityPlan`，入口默认可见（按钮现在在右上角常驻，但只有开关打开才渲染）。
- 面板文案中英文（现在只有中文；App 其余界面的语言约定以 `CityApp` 为准）。
- 小窗口：面板可折叠成工具条，不挡地图。
- 新手引导：第一次进入时三步引导（选建筑搬家 / 画路 / 撤销）。
- 依赖 P0 全部完成——大城市卡顿和扩档丢修改都不能带进正式版。
