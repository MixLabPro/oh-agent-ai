# City 路网优先代码设计说明书

日期：2026-10-08。状态：设计建议，尚未实现。
调研对象：`worktree-city-planner-v2`，HEAD `cb95634d`，并包含调研时已有的 `cityPlan.ts`、`planner/score.ts`、`planner/skeleton.ts` 未提交修改。本文不覆盖或认领这些修改。
本设计补充 `CITY_PLANNER_V2_SPEC.md`，明确连接安全、生成顺序与失败处理；不重启已完成的模块迁移。

## 1. 结论与实际流程

采用“城市结构意图 → 粗地理 → 连通骨架路网 → 公共设施选址与入口 → 街网 → 地块 → 最终校验”。不要把所有建筑坐标固定后再生成地理：河流、港口、海滨设施仍需要真实空间条件。降低复杂度的关键是减少反复改动已确定的道路与用地，而不是取消地理约束。

实际代码顺序为：

1. `createCityPlan` 决定 shape/biome/tier，按地块容量最多重建五次。
2. `buildGeography` 生成岸线、河道、山脊与 height/buildable。
3. `chooseCore` 选核心；`snap/place` 先落公共用地及地标。
4. `buildSkeleton` 生成主干、桥与环线高架。
5. 多遍移动用地：避高架、临街、贴岸、海上地标等。
6. 生成海滨大道、沿海路、河岸路、扇区街网，再补入口与孤立分量连接。
7. 合并碎边、断头收尾、运行九个修复策略（最多三轮）。
8. 校验车流路径、终筛地块、组装 CityLayout；普通会话建筑由下游布局消费地块。

因此当前不是“路网 → 地理”，也不是“所有建筑 → 路网 → 地理”。规划器模块化已推进，但阶段之间仍共享可变 Network/sites/blocks。

## 2. 已确认问题

| 问题 | 代码证据 | 修改方向 |
| --- | --- | --- |
| 公共设施在道路前锁定坐标，随后多次移动 | `cityPlan.ts` 的 place、避高架、临街、贴岸等段 | 先生成 SiteIntent，最终落位在骨架路网之后 |
| 连接逻辑多套 | `connectToNetwork`、入口桥接、孤立分量兜底、repairs | 一个连接器，共用合法性与接点规则 |
| 孤立分量最后直接加边 | `cityPlan.ts` 连通段 `tolerance=[1,0.7,0]` 后直接 addEdge | 禁止用降低硬约束换连通；失败返回原因 |
| 普通连接遇水拒绝，入口路另有桥逻辑 | safeRoadLink 与入口路 water-span 检查 | 桥梁作为连接结果的显式类型 |
| 平地断头被高度门槛排除 | constraints/networkRepairs 中 `height < 2.5` 跳过；平地高度约 1.2 | 根据端点用途和拓扑判定，不用高度代替道路语义 |
| 断头数与连通性混淆 | 现有 looseInlandRoadEnds 与生成期并查集 | 独立测量 disconnectedComponents、requiredEndpointDisconnected |
| 抽样占地不覆盖真实模型轮廓 | footprint 内外圈交错采样 | 快速圆包围初筛，旋转多边形最终检查 |
| 修复依赖执行顺序且缺少单步回滚 | solvePlan 顺序执行整张表 | 候选补丁评估后原子提交，输出未收敛诊断 |

当前未提交修改已纠正 parcelYield 的五倍分母差、门方向评分及岸线评分，并将环线评分改为连续区段检查。它们应单独验证后保留，不再作为待实现问题重复列入。

## 3. 阶段边界

建议新增内部类型，不改变渲染消费的 CityLayout：

```ts
type CityIntent = {
  seed: number; tier: number;
  districts: DistrictIntent[];
  sites: SiteIntent[]; // 区域、优先级、临水/临街条件，不是锁死坐标
};
type EndpointRole = "junction" | "site-access" | "cul-de-sac" | "must-connect";
type ConnectionRequest = {
  sourceNodeId: string;
  targetComponentId: string;
  purpose: "district-access" | "site-access" | "coastal-link";
  allowBridge: boolean;
  maxLength: number;
};
type ConnectionResult =
  | { ok: true; patch: NetworkPatch; cost: number }
  | { ok: false; reason: ConnectionFailure; attempted: number };
```

示意类型中的 DistrictIntent/SiteIntent/NetworkPatch/ConnectionFailure 在实现批定义；不要在运行时存储任何会话原文、路径或用户标识。规划只消费 seed/tier 和固定设计配置。

每阶段读只读上游产物、拥有自己的可变草稿。NetworkPatch 列出新增/删除边、共享节点、桥段及端点角色，提交前验证完整补丁。TypeScript Readonly 是接口约束，不等于深冻结；需通过所有权约定和测试防止修改上游对象。

市政核心、广场外环与桥位作为骨架保留区联合确定；其它公共设施不再先固定。海滨带先保留岸段与交通走廊，再选酒店/港口位置，避免“港口决定海滨带、海滨路又推动港口”的循环。

## 4. 统一连接器

### 4.1 有限搜索

按稳定顺序尝试：最近合法路段投影直连 → 利用已有道路连接 → 绕障碍的少量折线 → 有界网格 A*。网格搜索只用于前几级失败的必要连接，设置候选、搜索区域与扩展节点上限，避免每个断头全图搜索。

目标是已确认的主网分量；不能为了降低距离接到另一个孤立分量后就宣告成功。最终必须重新计算真实分量。

长度、转弯、坡度和造桥构成软成本；建筑净空、禁止水域、不可接受坡度是硬约束，任何降级不得取消。成本权重须配置化、记录版本。

### 4.2 桥梁与交叉

跨河允许返回 ground → bridge → ground 三段，检查桥头干地、跨距、桥下/桥上净空及入口坡道。河道用例优先；跨海长桥和高架立交单独处理，不从“遇水”自动推断可修桥。

与地面道路相交时，可在合法角度下创建路口并拆分原边，而不是全部拒绝。高架与地面几何相交不自动产生拓扑连接；必须显式生成匝道。现有 RoadEdge 难以完整表达高度层级时，在内部 patch 中保留结构信息，再由 finalize 适配；禁止输出失真的连接。

### 4.3 提交与失败

统一坐标规范化、吸附、边拆分和属性继承（宽度、道路等级、bridge）。补丁提交后重建受影响索引；车流只从最终网络生成。

失败分类至少包含 water-span、slope、site-clearance、junction-angle、search-budget、no-target。可选短支路允许移除；公共设施可换候选位置；必要主网连接失败则重选局部骨架或明确生成失败。不得静默返回名义坐标，也不得直接添加未检查的边。

## 5. 选址与地形

SiteSpec 收拢模型 footprint、入口局部坐标、临水要求、道路等级、优先级和可选性。候选沿骨架道路或岸线生成：车站入口朝最近道路，体育场预留入口与服务道路，港口保留陆侧货运入口与水侧码头，海上地标必须同时找到可行堤道。

候选接受前完成入口路线试算，避免“建筑合法但没有路”。生成期与修复期调用同一指派器。

第一批保留当前 height 函数，不引入地形重塑。后续若需要贴地打磨，可增加受限 TerrainPatch：只允许道路走廊小范围平整/桥头调整，保持河道连续、岸线与公共水域边界；规划、渲染和碰撞必须消费同一最终地形。不能只在渲染层加平台掩盖规划冲突。

普通建筑最后落位；道路定型后再切地块。若求解仍改变道路或设施，必须重切受影响地块并重算容量，而不是仅过滤掉冲突建筑后忽略容量损失。

### 5.1 自然环境调整边界

可以为交通基础设施适当调整环境，但分两批实现。首批道路适应现有地理：直连、绕行、桥接或换建筑候选；后续才允许受限的局部土木工程。禁止把地形重塑当成连接失败的无限兜底。

| 调整 | 首批 | 后续边界 |
| --- | --- | --- |
| 道路走廊小范围平整 | 不启用 | 限制挖填高度、影响宽度与过渡坡度 |
| 桥头整坡 | 使用现有合法桥头 | 允许局部整坡，不能堵塞河道或填掉水面 |
| 公共设施基座找平 | 检查实际 footprint，必要时换位置 | 有界调整，完整覆盖模型且与周围地面过渡 |
| 河流改道、填海、削山、全岛抬高 | 不启用 | 不属于本设计，另行设计与验收 |

后续 TerrainPatch 必须声明 `maxCut`、`maxFill`、`maxInfluenceWidth`、`maxTransitionSlope`、`maxTotalArea` 和 `maxIterations`。数值按现有世界单位、道路宽度和实测地形标定后固定成版本化配置；本设计不把未经验证的数值写成验收事实。任一参数缺失时禁用地形修改，超过预算时绕行或返回失败。

同时提交 NetworkPatch 与 TerrainPatch：先在草稿上验证两者，再原子接受；不得先改地形、后发现道路不可行而留下残余。多个地形补丁按稳定 id 顺序组合，重叠区域重新检查预算、坡度与水域边界。调整后重算受影响 height/slope/buildable、路段贴地、桥头和建筑基础；若尚无物理碰撞模块，不宣称已有物理保障，后续碰撞消费者也必须接入同一最终地形。

## 5A. 核心设计约束（实现不得放宽）

1. **安全优先于连通。** 不以降低建筑净空、水域保护、坡度和结构限制换取“连通率 100%”；失败有显式诊断。
2. **建筑坐标可重选。** 除核心与已确认基础设施保留区外，公共建筑先满足区域/临海/临街语义，最终坐标由可行候选决定。
3. **桥梁显式建模。** 普通地面边不得穿水；桥必须检查完整跨距、两岸接入和结构净空。
4. **几何交叉与拓扑连接分开。** 地面交叉建立共享节点；高架跨越不自动连接，匝道必须显式可行。
5. **局部地形调整有硬预算。** 超限不能不断扩大影响范围或提高预算，不能破坏河道连续性和保护水域。
6. **最终地形唯一。** 规划、渲染、建筑基础以及存在的碰撞消费者读取同一版本的最终 height；基础地形仅用于候选比较与回滚。
7. **确定性与无副作用失败。** 相同 seed/tier/配置/算法版本得到相同结果；搜索使用节点数预算而非墙钟超时；拒绝的候选不得修改正式网络或地形。
8. **派生产物最后生成。** 地块、普通建筑布局、植被与车流基于最终道路和设施；网络/地形版本改变时，相关缓存失效并重算。
9. **硬约束与软偏好分离。** 软评分不能允许非法方案，也不能阻止必要的安全修复；换位和连接必须先过同一套硬检查。

## 5B. 代码修改清单与完成条件

以下文件名为目标设计；新增文件必须在实际实现批创建。

| 文件 | 修改内容 | 完成条件 |
| --- | --- | --- |
| `planner/connect.ts`（新增） | 连接请求、有限候选搜索、桥接、失败原因、补丁试算 | 所有必要连接走统一入口；失败不改变正式数据 |
| `cityPlan.ts` | 替换 connectToNetwork、入口补路、孤立分量兜底；保留阶段编排 | 无绕过检查的直接兜底加边；不再多遍挪同一用地 |
| `planner/network.ts` | 节点吸附、边拆分、属性继承、NetworkPatch 提交 | 拆边保持等级/宽度/结构属性；共享节点真实可达 |
| `planner/constraints.ts` | 语义端点、最终连通、设施可达检查 | 平地断头可被测量；合法尽端有显式角色 |
| `planner/networkRepairs.ts`、`repairs.ts` | 删除高度盲区，修复通过连接器执行 | 生成与修复共用安全规则；不另写过水兜底 |
| `planner/sitespec.ts`、`assign.ts`、`access.ts`（新增） | 实际占地、入口、选址条件；骨架后指派 | 候选接受前入口可达；失败不回落到非法名义坐标 |
| `planner/footprint.ts` | 实际旋转占地终筛与共用几何检查 | 中心、边界、角点及道路扫掠宽度都纳入检查 |
| `planner/solve.ts` | 违例驱动、候选接受优先级、结束诊断 | 每次正式提交保持其它硬约束不恶化 |
| `planner/parcels.ts`、`finalize.ts`（新增） | 最终地块与渲染适配、容量和车流校验 | 不消费修复前失效网络；容量不足明确返回 |
| `planner/terrainPatch.ts`（后续新增） | 有预算的挖填、过渡、地形版本与回滚 | 首批不启用；补丁与道路共同接受，最终地形一致 |

连接器迁移时，需同步检查 `skeleton.ts` 高架出口的接驳线与角度/净空；不把它作为留在统一规则之外的特例。将 segmentDistance、节点 id 与容量规则等底层原语移入独立模块时，分批消除 planner 对 cityPlan 的反向运行时依赖，避免模块拆分后仍有循环依赖。

## 6. 求解与指标

先测量，再只触发相关策略。接受规则按优先级：硬约束违例减少且其它硬约束不恶化 → 必要连通改善 → 在前两项持平时比较软评分。不能因软分下降拒绝一个必要的安全修复。固定轮次上限仍保留，并报告结束原因、剩余违例、补路失败原因与策略触发数。

指标分开记录：孤立可用路网分量、必须接通端点、合法尽端、公共设施可达性、桥头连续性、容量、耗时。两个出口是重要街区的目标；地形受限街区允许有原因的单入口。无需对每个小街区强制双入口。

## 7. 迁移批次

1. 固化当前未提交修正的测试结果；记录已有残留 seed 与逐阶段耗时。独立修正端点高度盲区，保留新暴露缺陷的真实计数，不通过提高上限掩盖。
2. 抽取统一连接器，先保持正常连接行为；删除不安全直接加边兜底，补直连/绕行失败诊断。
3. 合并入口桥接与共享节点处理；新增最终连通约束。在固定复现 seed 上解决必要连接失败。
4. SiteIntent/SiteSpec/assign/access 落地，将公共设施最终坐标移到骨架后，逐类删除二次挪动遍。
5. 抽取街网与地块阶段；车流、容量和渲染产物基于最终网络统一 finalize。
6. 引入违例驱动补丁接受机制；测量后再决定半径校正和局部地形平整是否必要。

不同时改地形算法、道路算法和所有模型。纯抽取保持基线；行为变更逐批审查差异后更新基线。

## 8. 验收

- TypeScript/build，以及现有 baseline、constraints、solve、survey、seaside、layout、cross-engine 守卫按涉及范围运行。
- 合成场景：平地断头、建筑挡路、窄河可桥、宽河拒绝、坡度超限、T 路口拆边、反向端点、立体交叉不误连、无目标分量、安全失败无副作用。
- 后续地形批追加：挖填预算超限拒绝、河道不可被填断、补丁重叠确定性、道路与地形共同回滚、规划与渲染高度一致、地形变化后缓存和地块重新校验。
- 确定性：相同输入重复生成同一 patch；候选排序有稳定次级键，不依赖执行时间或未排序容器输入。
- 全档普查记录每类违例的岛数与总数；必要公共设施可达、所有保留街区接入主网；合法尽端必须有角色与原因。
- 性能测量给出设备、冷/热运行、各阶段与整图 p50/p95、半径重建次数、A* 扩展数；对照同 seed 的旧版，单岛耗时目标不超过对照 1.5 倍。本文不把此前性能数字当本次测量。
- 固定复现岛截俯视、桥头、海滨入口和地标近景；检查道路实际连续、模型净空与贴地效果。截图必须绑定 seed/tier/commit/配置。
