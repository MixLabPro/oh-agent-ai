## 不可并行的边界

1. A 的本地数据合同、结果版本和价格/证据语义先稳定；B 和 C 不得各自计算金额或维护第二套配置。
2. B 的首份 L0 结果依赖 A 的查询及口径，但其 UI、来源发现和导入流程可在 A 的稳定契约上并行。
3. C 的计费确认、预算、提醒、菜单栏与会话视图必须共用 A 的声明、影响预览和版本化重算链路。
4. D 可提前准备性能数据集、文档和打包脚本，但签名公证、迁移演练及正式安装验收只能在功能稳定的 RC 上完成。
5. E 不是代码测试的替代品；外部试用、签名公证与真实设备证据都不能预先勾选。

## 当前已证实的部分完成项

- REQ-034：无预算时保持“预算未设置”。
- REQ-103：公共价格目录不含个人订阅、付款、路由或预算。

这些完成项不代表所属阶段完成。每阶段完成须同时满足该阶段文档列出的退出条件，并将权威 PRD 中对应条目逐项更新。

## 统一验证基线

除定向测试外，每个阶段合入前至少运行受影响范围的 Rust/Python 测试；D 和 E 必须完成 PRD 的完整发布门禁：Python 全量测试、golden、Rust release 测试与 clippy、Rust/Python parity、桌面及相关集成测试。不得更新 snapshot 或删除断言来掩盖行为变化。
