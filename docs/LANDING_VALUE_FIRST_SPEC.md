# Landing 价值优先改造 Spec（真实证据先行 · 海外首发）

> 状态：**Draft v1.1（2026-09-30，评审修订；未实施）**。
> 触发：landing 重构版（`8a050094`）复查后的营销/增长分析 + 「Reddit 用户只认
> 你能产出什么、是否响应他们的痛点」的定位校准。重构版在事实精度、
> 无客户端分析脚本、
> a11y、美学上已达标；本 spec 解决的是**价值呈现结构**：痛语言 hero、真截图
> 证据位、「它替你抓什么」价值清单。CLI、安装通道及渠道实验改为独立后续
> 决策，不再作为真实证据版 landing 的发布前置项。
> 前置：产品侧已有会话诊断与总览发现入口；当前总览发现入口可能只到宿主
> 会话列表，并不保证直达具体诊断，截图与动线须以待发布版本实测。
> 关联：`OVERVIEW_DRILLDOWN_AND_INLINE_FINDINGS_SPEC.md`（产品侧能力）、
> 精益画布讨论（首发四页与付费边界）、数据保留与 serving-face 政策
> （不上传 Session 数据是产品原则，不是营销姿态）。

## 0. 一句话结论

把 landing 从「定位优先」调整为「痛点 + 产品真实证据 + 可核对边界」：
hero 用已有会话诊断能回答的问题开场；三组真机证据分别展示失败定位、
用量/会话穿透与计费口径。保留本地隐私、MIT、啄木鸟与工作收据视觉资产。
**发布门：无真截图或截图无法完成所述动线则不发布对应承诺。** 新 CLI、
安装脚本、月度浪费金额与通知均不得倒逼 landing 超前承诺。

## 1. 不可变决策（实施期间不重开）

1. **无客户端分析脚本与用户级追踪。**不引入分析脚本、字体 CDN、社交
   小组件或用户级分流。若后续做第一方渠道级归因，需说明服务器访问日志
   仍可能包含 IP/UA，定义保留期与脱敏方式；不能把它称为绝对「零追踪」。
2. **痛语言必须由实物回答。**hero 和价值清单先说具体问题，再用截图
   展示输出；不得用额度耗尽、任务进度或节省金额等当前诊断不能证明的因果
   问句。原有「工作交给 Agent，掌控留给你」可留作辅助品牌句，不再独占首屏。
3. **证据必须是真的。**hero 与价值清单的图只能是真机产品截图（带口径标签/
   失败标记的原样界面，允许裁剪与缩放，不允许合成数字）；截图位用显式
   占位机制，`verify-landing` 的发布门检查占位必须清零。mock 演示区保留
   但明确降级为「交互示意」，不承担证据职能。
4. **下载路径只展示已可用渠道。**首发沿用可验证的 macOS Release 与
   安装说明；新 CLI 命令、brew tap 或安装脚本均需分别开发与安全验收，
   不能作为本轮 landing 上线前置项。
5. **诚实边界同步翻译成痛语言。**FAQ 可补商业模式与竞品比较，但免费/
   付费边界未正式确定前不虚构承诺；竞品能力在发布时复核，只陈述可验证
   差异，不贬损。
6. **a11y 与既有工程纪律不动**：skip-link/aria/reduced-motion 模式延续；
   页面保持纯静态（HTML+CSS+原生 JS，无构建链）；资产变更走仓库提交。
   落地页本身获得与产品同级的**契约脚本**（`verify-landing.mjs`）。
7. **海外发布先有英文证据。**面向 Reddit/X 的英文页面、英文真机截图、
   英文安装说明与术语校对须同时就绪；中文页可以保留，不以中文唯一版本
   承接海外首发。

## 2. 现状与缺陷（证据）

| # | 缺陷 | 证据（website/landing/index.html） |
|---|---|---|
| 1 | hero 缺可立即验证的具体问题 | `<h1>工作交给 Agent。掌控留给你。</h1>`（:42）有品牌感，但尚未回答「会得到什么结果」 |
| 2 | 首屏证据为 mock | 演示窗「数字全部为模拟数据，不是真实界面截图」（:90 自我声明）；产品真能力（失败诊断/深链/口径）无一张真图 |

| 5 | 增长归因待设计 | 当前无渠道归因；第一方日志能统计站内访问，跳转 GitHub 后不能直接证明实际下载 |
| 6 | FAQ 可补高意图答案 | 无商业模式条与 ccusage 对比条；商业边界需先定，竞品事实需发布时复核 |

| 9 | 价值能力↔痛语言无对照表 | 可说「反复失败涉及多少输入」，不能把相关 Token 直接译成「白烧」 |

## 3. 页面目标结构（改造后）

```
Hero        可由现有诊断回答的痛问句 + 一句价值 + 已可用下载 CTA + 真截图
它替你抓什么  3 组证据：重复失败定位 / 用量到会话 / 三类计费口径
产品演示      现 mock 交互窗（明确为交互示意，不承担真实性证明）
工作方式      三步保留并与三组证据对应
本地隐私      保留（核心信任资产）+ 无客户端分析脚本说明
FAQ         补真实商业边界与经复核的竞品差异
下载区       收据动画保留 + 可用安装路径与系统要求
```
英文页作为海外分发入口；中文页继续服务中文受众。双 Hero 变体与渠道赛马
仅在流量、承接与归因方案足以评估时另案实施。

## 4. 设计

### 4.1 L0 · 工程底座（~0.5 天）

1. **`website/landing/tools/verify-landing.mjs` 契约脚本**（Node、无依赖；
   以实际仓库脚本位置为准）：
   - 检查本地资产与禁止的客户端追踪请求；允许的外部链接按明确用途维护，
     不把所有 `https?://` 文本都误判为网络请求。
   - **发布门**：首发证据位的真图、mock 示意标注、口径边界、隐私说明、
     下载链接、英文页与 a11y 关键属性均在场；对残留占位与外链脚本做
     负向自测。静态检查不能代替截图人审与动线手测。
   - 挂入仓库校验惯例（README 说明 + 可选 npm script）。
2. 页脚声明：`本页不使用客户端分析脚本，不上传 Session 数据。` 如后续
   采集第一方访问日志，公开其用途、字段与保留期。
3. FAQ 在商业边界确定、竞品事实复核后补充；未定事项明确写「尚未公布」。

### 4.2 L1 · Hero 痛语言 + 真截图位（工期待截图脱敏与动线确认）

1. Hero 备选：H1 `Agent 还在运行，哪次会话已反复失败？`；副句：
   `在 Mac 上查看受支持 Agent 的用量、计费依据和失败区间，回到会话轨迹
   核对证据。Sessions 不上传云端。` 英文版需按目标用户语感重写，
   不是机械翻译。不得用「额度 40 分钟烧完」暗示尚不能证明的额度归因。
2. **截图占位机制**：`<figure data-shot="hero-diagnostics" data-required="true">`
   内放显式「待真截图」占位；发布前替换为真实且经隐私人审的产品图。
   截图应展示诊断与证据入口，不能只展示经修饰的数字卡。
3. og:image 可用真实界面裁剪与品牌排版，但画面中的数据与 UI 不合成；
   海外版分享卡与落地页语言一致，先做一个可验证的版本。

### 4.3 L2 · 「它替你抓什么」三组证据

每组都用「具体问题 → 产品原样输出 → 点击后到哪里 → 能力边界」四步，
避免五张同质卡堆砌：

| 组 | 问题标题 | 必须能在产品里复现的输出 | 边界 |
|---|---|---|---|
| B1 | 哪次会话在反复失败？ | 重复失败诊断、命中回合和证据检查入口 | 涉及 Token 不等于浪费或可节省 Token |
| B2 | 用量集中在哪些会话？ | 时间/宿主用量 → 会话列表 → 所选会话详情 | 只称「一键到会话」当入口确实能直达该会话；否则展示真实的两步动线 |
| B3 | 这笔钱是账单还是估算？ | 订阅、按量估算、已知账单及未知项的原样口径 | 不同币种与 basis 不混加；估算不等于实付 |

原 B4 额度与 B5 输入膨胀可以放在后续专题或 FAQ；只有宿主能力、
真实数据和截图都通过验收才升级为首页主价值卡。啄木鸟与收据动画保留
为品牌视觉，不承载未实现的数字承诺。

### 4.4 L3 · 英文承接与现有下载路径

海外版页面、截图、CTA、FAQ 与 Release 安装说明必须用一致的英文术语。
首版仅链接已发布且可验证的 macOS 安装渠道；下载前告知系统要求、
受支持宿主、首次无数据/权限不足的处理方法。不要展示尚不存在的
`agent-vitals vitals`、brew tap 或 `install.sh`。

### 4.5 L4 · 后续可选项目：CLI、分发与渠道实验

CLI 摘要命令属于产品功能，需要另立只读语义、口径、空库降级与 Rust/Python
兼容测试；安装脚本属于供应链安全项目，不能以脚本内、同源提供的 checksum
视为独立可信校验。渠道 `ref` 只能说明入口来源；网站日志无法直接证明
GitHub Releases 的实际下载或安装。若要实验双 Hero，先定义基线、样本量、
渠道分层、隐私告知与可观测的转化事件，不以「两周/三个渠道/平局选费用」
作为预设胜负规则。

## 5. 明确不做

- 不做用户级 A/B 与任何客户端状态（ Cookie/localStorage 分流）。
- 不引入构建链/框架/客户端分析；英文版是海外发布条件，不做未经审校的机械翻译。
- 不在 landing 承诺额度正向余量、省钱比例、自动优化。
- 分享卡片生成（产品内导出即得分享图）是**产品侧**后续项，本 spec 只做
  静态 og 分享卡。
- 不在首版 Hero 展示月度疑似浪费金额、实时止血或自动干预。
- 内容锚点/SEO 专栏可后续独立规划。

## 6. 分期与进度（每阶段验收绿后打勾）

- [ ] **L0 工程底座**：契约脚本、页脚准确隐私声明、FAQ 已定事项
- [ ] **L1 Hero**：可由实物回答的问题 + 经人审的真截图 + 真分享卡
- [ ] **L2 三组证据**：产品动线与截图逐项验收，边界与口径同屏
- [ ] **L3 海外承接**：英文页面/截图/安装说明及真实可用下载入口
- [ ] **发布门**：Hero + 三组证据真机素材、动线、隐私/a11y/移动端回归
- [ ] **L4 后续独立决策**：CLI、安装分发、渠道归因/双钩实验；不阻塞首发

## 7. 验收标准

1. `node website/landing/tools/verify-landing.mjs` 绿；对外链脚本与残留
   占位各有负向自测。若脚本采用其他路径，以仓库实际文件为准并更新本条。
2. 手测中英页面、下载 CTA、首装说明和三组「截图 → 应用动线」；不能只看
   静态截图存在，还要确认对应入口与目标数据在当前版本可用。
3. 发布门记录每张图的界面、版本、口径标签、隐私人审与目标动线。
4. 既有页面纪律回归：mock 标注、a11y（skip-link/aria/reduced-motion）、
   深色适配不回退。

## 8. 风险与守卫

| 风险 | 守卫 |
|---|---|
| 截图含敏感路径/提示词 | 只截脱敏面（口径卡/诊断汇总/会话列表），发布前人审；与 serving-face 政策同标准 |
| 痛语言暗示未实现的因果归因 | 每个问句都由当前版本截图和可复现动线回答；禁「白烧金额」「额度由哪次会话耗尽」 |
| 英文页与产品输出不一致 | 英文真机截图与安装说明同版验收；遇到中文残留明确列为发布缺口 |
| 第一方访问日志被误称零追踪 | 无客户端分析脚本与无 Session 上传分开陈述；后续归因需披露日志字段与保留期 |
| 下载链路中断 | 使用已发布安装渠道，首装/权限/空数据状态手测；新脚本另案安全审查 |

## 10. 后续诊断内容位的发布条件（与成本暴露 spec 对齐）

`WASTE_ATTRIBUTION_SPEC.md` v1.1 已将原「疑似浪费金额」方案收紧为
**单会话失败区间成本暴露**。它并不证明可避免性，因此原 v1.0 的 Hero
浪费读数、月度「白烧金额」头条、浪费收据与数字 og 卡**全部撤回**，
不得作为已排期的内容位。即使 S1 实现，也只可在解释型专题中展示：
「这段重复失败涉及多少输入与名义成本」，紧邻证据、计费 basis、
正常工作混入说明和不可节省声明；不放入首屏省钱承诺。

通知专题须等该 spec 的 S3 独立验收：触发时效、默认关闭、持久去重、
点击到证据等都实测通过后，才可说「检测到新的重复失败后提醒」，
不能说「实时止血」或「正在白烧时提醒」。未来若建立事实级血缘、
可避免性证据和经审查的浪费指标，须另立口径与营销措辞评审，
不得自动恢复旧图或旧文案。
