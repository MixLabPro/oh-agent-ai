# Landing 价值优先改造 Spec（Reddit 语境 · 痛语言 + 真证据 + 终端路径）

> 状态：**Draft v1.0（2026-09-29）**。

> 你能产出什么、是否响应他们的痛点」的定位校准。重构版在事实精度、零追踪、
> a11y、美学上已达标；本 spec 解决的是**价值呈现结构**：痛语言 hero、真截图

> 双钩赛马与渠道归因。

> 精益画布讨论（首发四页与付费边界）、数据保留与 serving-face 政策

## 0. 一句话结论

把 landing 从「定位优先」（漂亮的口号 + mock 演示）改为「价值优先」（他们
的痛的原话 + 真实产品输出 + 60 秒自证）：hero 用痛问句开场并放**真截图**，
新增「它替你抓什么」价值清单区（能力 × 痛语言 × 证据图），终端一行命令让
Reddit 用户在帖子里就能跑出**自己的数字**，零追踪约束下用渠道级变体与第一方
ref 归因完成双钩赛马。**发布门：截图位未填真图不得发布**——诚实产品的
landing 不允许「截图比实物好」，也不允许「实物比截图好却看不见」。

---

## 1. 不可变决策（实施期间不重开）

1. **零追踪是不可协商底线。**不引入任何分析脚本、字体 CDN、社交小组件；
   页脚落「本页无任何分析脚本」声明；归因只许第一方（下载/命令链接带
   `?ref=`，由自家服务器访问日志计数）。变体测试是**渠道级**（不同 ref/
   路径指向不同 hero 变体），不做用户级分流——那需要状态，状态即追踪。
2. **痛语言优先于定位语言。**hero 与价值清单的每一句必须能作为 Reddit
   帖标题存活（痛的原话 + 你产出什么）；「掌控」「伙伴」类抽象词不进首屏。
   品类叙事（谁来检查 Agent）退守 og:title 与分享卡。
3. **证据必须是真的。**hero 与价值清单的图只能是真机产品截图（带口径标签/
   失败标记的原样界面，允许裁剪与缩放，不允许合成数字）；截图位用显式
   占位机制，`verify-landing` 的发布门检查占位必须清零。mock 演示区保留
   但明确降级为「交互示意」，不承担证据职能。
4. **终端命令读真数据、零副作用。**新 CLI 子命令只读权威库（走既有 memo
   只读面），不写库、不触发同步、不要求 GUI 安装；输出为终端友好的分层
   口径摘要。安装渠道分级落地（brew tap 未就绪前用带校验的安装脚本），
   不降级为「去 GitHub 自己找」。
5. **诚实边界同步翻译成痛语言。**FAQ 补两条：商业模式直答（免费版边界）、
   「和 ccusage 比呢」诚实对比（承认对方在纯 token 统计上同样优秀，差异在
   会话追溯/失败诊断/口径/本地 App）。比较只陈述能力差异，不贬损。
6. **a11y 与既有工程纪律不动**：skip-link/aria/reduced-motion 模式延续；
   页面保持纯静态（HTML+CSS+原生 JS，无构建链）；资产变更走仓库提交。
   落地页本身获得与产品同级的**契约脚本**（`verify-landing.mjs`）。

## 2. 现状与缺陷（证据）

| # | 缺陷 | 证据（website/landing/index.html） |
|---|---|---|
| 1 | hero 是定位抽象而非痛语言 | `<h1>工作交给 Agent。掌控留给你。</h1>`（:42）——Reddit 视角信息量为零 |
| 2 | 首屏证据为 mock | 演示窗「数字全部为模拟数据，不是真实界面截图」（:90 自我声明）；产品真能力（失败诊断/深链/口径）无一张真图 |
| 3 | 最 Reddit 相性的内容被折叠 | 失败诊断藏在「工作方式」第三步（:171-179）；价值清单区不存在 |
| 4 | 无终端路径 | CTA 仅「获取 macOS 测试版」→ GitHub releases 列表（:245）；无 brew/一行命令 |
| 5 | 无归因与变体机制 | 下载链接无 ref；双钩（费用 vs 掌控）无从对比 |
| 6 | FAQ 缺两条高意图答案 | 无商业模式条；无 ccusage 对比条（7 条 FAQ 通检） |
| 7 | og:image 是应用图标占位 | `<meta property="og:image" content="assets/app-icon.png">`（:8） |
| 8 | 页脚无零追踪声明 | footer 只有 MIT/反馈/©（:257-267） |
| 9 | 价值能力↔痛语言无对照表 | 仓库语言（session consumption diagnostics）与用户语言（反复失败白烧 token）之间无翻译层 |

## 3. 页面目标结构（改造后）

```
Hero        痛问句 + 一句价值 + 双 CTA（下载 | 终端一行命令）+ 真截图证据位(A)
它替你抓什么  5 张价值卡：痛语言标题 × 一句产出 × 真截图/证据位(B1..B5)
产品演示      现 mock 交互窗（降级为「交互示意」，文案明示）
工作方式      三步保留（已是问题开场，微调对齐价值清单）
本地隐私      保留（已是强项）+ 页脚零追踪声明
FAQ         +商业模式 +vs ccusage（其余保留）
下载区       收据动画保留 + 终端命令卡 + ref 参数说明（不面向用户展示）
```
渠道变体：`/index.html`（默认=掌控钩）与 `/billing.html`（费用钩
「3.2 亿 token，哪个任务烧的？」）——同资产双入口，社区帖按渠道选用。

## 4. 设计

### 4.1 L0 · 工程底座（~0.5 天）

1. **`tools/verify-landing.mjs` 契约脚本**（node，无依赖，`node --check` 级）：
   - **零网络审计**：解析 index/billing 的 html+js+css，外部 URL 白名单仅
     `github.com/MixLabPro/*`（含 OG 链接）；出现任何其它 `https?://`、
     `<script src=` 外链、`@import`、`fetch(`/`sendBeacon` 即红。
   - **发布门**：`data-shot` 截图占位必须清零（占位机制见 L1）；
     「模拟数据」标注必须存在于演示区；FAQ 必须含商业模式与对比两条
     关键句；页脚含零追踪声明；`?ref=` 只出现在下载/命令链接。
   - 挂入仓库校验惯例（README 说明 + 可选 npm script）。
2. 页脚声明：`本页无任何分析脚本、字体与追踪——和产品同一个原则。`
3. FAQ 两条新增（措辞走 §1-5 的诚实对比纪律）。

### 4.2 L1 · Hero 痛语言 + 真截图位（~0.5 天 + 截图）

1. 默认变体 hero：
   - H1：`额度 40 分钟烧完，是哪个会话干的？`
   - 副句：`Agent Vitals 在你的 Mac 上读 Agent 留下的记录：哪次在反复失败、
     哪笔钱花在哪、订阅盖住了什么——追到具体会话，数据不出本机。`
   - `/billing.html` 变体：H1 `3.2 亿 token，哪个任务烧的？`（费用钩），
     其余同构。
2. **截图占位机制**：`<figure data-shot="hero-diagnostics" data-required="true">`
   内放占位盒（显式「待真截图」标记）；L4 发布门前 `verify-landing` 扫描
   `data-required` 的 figure 必须含 `assets/shots/` 真图。占位盒在页面上的
   样式与真图等尺寸，替换即排版不变。
3. og:image 换**真分享卡**（1200×630：黑底 + og:title 问题钩 + 一张真实
   诊断界面的裁剪 + 口径小标签）；两个变体各一张。

### 4.3 L2 · 「它替你抓什么」价值清单（~1 天）

五张卡（标题=痛语言，正文=一句产出，右/下=真截图位 B1..B5）：

| 卡 | 痛语言标题 | 产出句 | 截图（真机） |
|---|---|---|---|
| B1 | 后台反复失败，token 白烧 | 连续失败/重试风暴点名到会话与调用 | 失败诊断视图 |
| B2 | 账单里那笔钱，说不清是谁花的 | 消耗 → 会话一键穿透，逐回合证据 | R1 深链动线 |
| B3 | 订阅到底盖住了什么 | 订阅/按量估算/账单确认三本账分栏，未知不冒充零 | 三级口径卡 |
| B4 | 额度什么时候回来 | Claude 耗尽+重置时刻、撞窗计数；Codex 真实余量 | 额度卡（分宿主诚实标注） |
| B5 | 这次为什么贵了 4 倍 | 输入组成/缓存命中/输入膨胀摆出来 | 会话组成分解 |

每卡底部一行小字：能力边界如实（如 B4 注明「Claude 官方不提供正向余量，
只显示已耗尽与重置时刻」）。美学资产（啄木鸟/收据动画）保留为区间装饰，
不承载信息。

### 4.4 L3 · 终端一行命令（~1.5 天）

1. **CLI 新子命令 `agent-vitals vitals`**（命名避开通用量词；`--json` 同
   供脚本用）：只读权威库，输出终端摘要——今日/本月 token、三级口径金额
   （含「未知不计为 0」行）、最贵 3 个会话（含「查看轨迹的命令提示」）、
   若有活跃发现则 top1 一行。中文、ANSI 着色、≤24 行；数据缺失各段如实
   标 unavailable。实现走 query crate 只读面 + 既有 ReadMemo；golden/CLI
   测试按惯例新增（`--json` 形状冻结）。
2. **安装通道分级**：一级 `brew install MixLabPro/tap/agent-vitals`（tap
   未就绪前隐藏）；二级 `curl -fsSL <release>/install.sh | sh`（脚本做
   checksum 校验，随 release 产出）；页面默认展示二级，brew 就绪切换。
3. hero 双 CTA：`下载 macOS 测试版`｜`终端先看：一行命令`（命令可复制，
   hover 展示示例输出截图——真终端截屏）。
4. 命令与下载链接统一挂 `?ref=` 位（默认无 ref，社区分发时加）。

### 4.5 L4 · 双钩赛马 + 渠道归因（发布期启用，~0.5 天）

1. 社区帖按渠道选变体（掌控 `/`、费用 `/billing.html`），链接带
   `?ref=<channel>`；
2. 归因=第一方访问日志对 `/releases` 外点与 install.sh 的 ref 计数；
   周度人工汇总（无面板，文本报告即可）；
3. 赛马判定线：两变体各至少 3 个渠道/两周窗口，比较下载转化；平局则
   hero 采用费用钩（已验证需求优先）。

## 5. 明确不做

- 不做用户级 A/B 与任何客户端状态（ Cookie/localStorage 分流）。
- 不引入构建链/框架/分析；不做多语言（中文唯一，EN 后议）。
- 不在 landing 承诺额度正向余量、省钱比例、自动优化。
- 分享卡片生成（产品内导出即得分享图）是**产品侧**后续项，本 spec 只做
  静态 og 分享卡。
- 内容锚点/SEO 专栏、README 对齐为后续独立 spec（本 spec 只立骨架不留债）。

## 7. 验收标准

1. `node tools/verify-landing.mjs` 绿（零网络审计 / 发布门 / 文案关键句 /
   ref 纪律）；对故意注入的外链与残留占位各有一次**负向自测**（注入即红）。
2. 手测：`index.html` 与 `billing.html` 双变体渲染正常（本地 serve 200）；
   hero 双 CTA 可达；终端命令在含真实数据的本机输出 ≤24 行且三口径齐备。
3. 发布门执行记录：截图回填清单（哪张图、来自哪个界面、口径标签可见）。
4. 既有页面纪律回归：mock 标注、a11y（skip-link/aria/reduced-motion）、
   深色适配不回退。

## 8. 风险与守卫

| 风险 | 守卫 |
|---|---|
| 截图含敏感路径/提示词 | 只截脱敏面（口径卡/诊断汇总/会话列表），发布前人审；与 serving-face 政策同标准 |
| 痛语言过度承诺（「找出白烧」被读成自动修复） | 卡片正文与 FAQ 双处声明「提供线索，不替你判断」；措辞评审过 verify-landing 关键句 |
| install.sh 被中间人替换 | 脚本内 checksum 校验 + 页面明示校验值；brew 就绪后切一级 |
| 双变体分裂权重（SEO 双入口） | billing.html `<link rel=canonical>` 指 index；robots noindex 于 billing |
| CLI 摘要口径与 GUI 不一致 | 同走 query 只读面同一 SQL（复用 R3 已收敛的 memoized 路径），测试对拍 GUI `read_overview` 数字 |

## 10. V1.2 增补 · 浪费内容位（依赖 `WASTE_ATTRIBUTION_SPEC.md`，2026-09-29）

浪费量化（S1）与失败风暴告警（S2）落地后，landing 解锁五个新内容位。
**上页铁律不变**：只展示已合入并截到真图的能力；浪费措辞与产品内 UI 契约
共用一个词表；数字必须带粒度小字。

### 10.1 措辞词表（与 waste spec §4.1 的 UI 契约同步，verify-landing 断言）

- **允许**：「疑似浪费（估算）」「估算机会」「按回合粒度上界估算」「tokens」。
- **禁止**：「可节省」「省下」「已浪费 ¥X（能省回）」任何变体；裸金额
  （金额必须与「疑似/估算」限定词和粒度小字同现）。
- `verify-landing` 增加浪费措辞组断言：允许词在场时粒度小字必须在场；
  禁词表命中即红（对 hero/价值卡/og 文案三处生效）。

### 10.2 五个内容位与上页时序

### 10.3 叙事补全

「Most agent failures don't crash. They decay.」+「Every tool call
succeeded. The Agent still failed.」之后追加第三句（真数字）：
**「上个月，它悄悄值 ¥86（估算）。」**——decay 叙事获得价格标签。
